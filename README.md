# bpl-cbr-fusion

Bayesian Program Learning（BPL）と事例ベース推論（CBR）の融合を検証する研究プロジェクト。

## 位置づけ

「間違っていたからではなく、枯れた／当時は割に合わなかったために捨てられた理論を救う」取り組み（理論救済台帳）のエントリ001。対象の2理論は別々に死んだが、死因はどちらも「当時の道具立て」にある：

- **BPL**：概念を生成プログラムとして学ぶ。型（文法＋部品ライブラリ）を事前構造とし、少量の観測からプログラムを逆推論する。死因はプログラム探索の計算コスト。
- **CBR**：知識はルールではなく事例。検索→再利用→修正→保存の循環で解く。死因は事例ベースの構築・保守コストと、適応の手書き依存。

今は、埋め込み検索が安くなり、安いモデルがプログラム候補の提案者・適応の実行者になれる。死因が解消したいま、両者を接合すると何が起きるかを検証する。

## 仮説

事例が型を呼び出し、適応の成否が型を育てる系は、単体より次の点で優れるはず：

1. 純粋なプログラム探索（BPL単体）より探索量が少なく速い ― 似た事例のプログラムが初期候補になるため。
2. 純粋な事例の使い回し（CBR単体）より分布の外へ一般化できる ― 事例ではなく型を介して解くため。
3. 経験が貯まるほど系全体が軽くなる ― 繰り返す修正パターンが型へ抽象化（昇格）され、事例ベースも型ライブラリも圧縮されていくため。

## アーキテクチャ（スケッチ）

1. **事例ベース**：（問題、プログラム、実行結果、修正履歴）の蓄積。
2. **想起**：類似事例を検索し、そのプログラムを初期候補にする。なければ型ライブラリの部品から合成する。
3. **適用・修正**：プログラムを実行し、失敗箇所を局所修正する。
4. **保存**：成功した（問題、プログラム）の組を事例として登録する。
5. **昇格（圧縮）**：繰り返し現れる修正パターンを抽象化し、型ライブラリの部品へ昇格させる。元の事例は「どの型からどう作ったか」の参照に置き換わる。

肝は 5。CBR の肥大化問題への回答であり、BPL 系のライブラリ学習との接合部になる。
