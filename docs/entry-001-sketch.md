# 設計スケッチ：エントリ001「BPL × CBR 融合」

作成：2026-11-10（プロジェクト「枯れた理論の救済」の初手としてユーザーが選定）

## プロジェクトの形（仮）

- 仮称：Theory Rescue（理論救済）。リポジトリ名候補：`theory-rescue`
- 理論ごとに1エントリを積む「救済台帳」形式：①元の主張 → ②死因の診断 → ③当時と今で何が変わったか → ④最小実験 → ⑤判定（復活／条件付き／やはり故人）
- 死因の5分類：計算コスト／データ不足／工学的重さ／流行・制度／後継への包含の誤認

## 対象理論と元の主張

**Bayesian Program Learning（BPL）**
概念は「生成プログラム」として学ばれる。型（文法と部品ライブラリ）が事前構造としてあり、少量の観測から最もらしいプログラムを逆推論する。人間が数例で概念を掴める理由の説明として提案された。

**事例ベース推論（Case-Based Reasoning, CBR）**
知識はルールではなく事例の集積。新しい問題は「検索 → 再利用 → 修正 → 保存」の循環で解く。学習とは事例が増えること。

## 死因の診断

- BPL：**計算コスト**。プログラム空間の探索が爆発し、スケールしないと見なされた。あわせて「大規模データ＋勾配降下で十分」という包含の誤認も効いた。
- CBR：**工学的重さ**。事例ベースの構築・保守コストが高く、適応の部分が結局手書きルールに依存した。

## 当時と今で何が変わったか

- 埋め込み検索が安く速くなり、CBR の「検索」は実質タダになった（RAG の隆盛が傍証）。
- 安い LLM／モデルが「プログラム候補の提案者」「適応の実行者」になれる。探索に賢い提案分布が与えられるようになった。
- DreamCoder が「解いた経験からライブラリ（型）を育てる」方式の実現可能性を部分的に実証した。

## 融合の仮説

事例が型を呼び出し、適応の成否が型を育てる系は、次の3点で単体より優れるはず：

1. 純粋なプログラム探索（BPL単体）より、探索量が少なく速い ― 似た事例のプログラムが初期候補になるため。
2. 純粋な事例の使い回し（CBR単体）より、分布の外へ一般化できる ― 事例ではなく型を介して解くため。
3. 経験が貯まるほど系全体が軽くなる ― 繰り返す修正パターンが型へ抽象化（昇格）され、事例ベースも型ライブラリも圧縮されていくため。

これはユーザーの循環モデル（世界のルール同定 → 型の形成 → 型の書き換え → 経験がルール同定を進める）の、検証可能な形での具体化である。

## アーキテクチャ（スケッチ）

1. **事例ベース**：（問題、プログラム、実行結果、修正履歴）の蓄積。
2. **想起**：類似事例を検索し、そのプログラムを初期候補にする。なければ型ライブラリの部品から合成する。
3. **適用・修正**：プログラムを実行し、失敗箇所を局所修正する。修正の提案者は当面、単純な編集操作＋安いモデル（dsh の DeepSeek V4.1 Flash）の併用を想定。
4. **保存**：成功した（問題、プログラム）の組を事例として登録する。
5. **昇格（圧縮）**：繰り返し現れる修正パターンを抽象化し、型ライブラリの部品へ昇格させる。元の事例は「どの型からどう作ったか」の参照に置き換わり、ベースは軽くなる。

肝は 5。これが CBR の肥大化問題への回答であり、BPL 系のライブラリ学習に相当する接合部になる。

## 最小実験の候補

- **A. 文字列変換（FlashFill 風）**：入出力の例から変換プログラムを学ぶ。成否が機械判定でき、事例が自然に貯まり、型への昇格が見えやすい。**推奨**。
- **B. グリッド世界のルール帰納（ARC-lite 風）**：ユーザーの嗜好には合うが、評価系の用意がやや重い。
- **C. 小規模ボードゲームの戦術**：面白いが初手には大きい。

## 比較対象と評価指標

比較対象：①事例のみ（再利用＋最小の適応） ②プログラム探索のみ（事例なし） ③融合（本命） ④参考として LLM の直接回答。

評価指標：

- 経験量に対する新規問題の成功率（学習曲線の立ち上がり）
- 1問あたりの探索・適応コスト
- ライブラリの成長記録：部品数、昇格の回数、事例ベースの圧縮率

## 実装メモ

- プロトタイプは Python（反復速度優先）。Voliq とは別プロジェクトなので Rust には縛らない。
- 実装補助と修正提案者に dsh（DeepSeek V4.1 Flash via OpenCode Go）が使える。
- GPU が必要になれば Colab CLI を使う（セッションは使い終わるたびに終了）。
