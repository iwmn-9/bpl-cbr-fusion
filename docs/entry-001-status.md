# エントリ001 実装状況（2026-11-11 時点）

対象：`docs/entry-001-sketch.md` の「BPL × CBR 融合」。この文書は実装の現状と、スケッチとの差分を正直に記録するためのもの。

## 実装済み

- 文字列変換の骨格：`dsl.py`（変換プログラムの表現と実行）、`cases.py`（事例ベース）、`solver.py`（テンプレート→再利用→修正→探索）、`demo.py`。
- 昇格 v1（`library.py`）：解けた事例のプログラムが同じ骨格で再帰したら、異なるリテラルをスロット化（反単一化、Plotkin 1970）して型テンプレートとしてライブラリに昇格させる。被覆された事例は「テンプレート＋バインディング」の参照として保存される。solve の順序は テンプレート→再利用→修正→探索 で、全経路のコストを `candidates_tested` で計測する。
- 修正（revise）ステップ＋実行適格ゲート＋完全試行記録：再利用に失敗した候補（類似度ランキング上位3件）に単一編集を適用する。ティア順は 値置換→部品交換（swap）→部品挿入（insert）→部品削除（remove）で、いずれも1編集・決定的順序。値置換は常に試行し、構造ティアはソースプログラムが対象例の全入力で DslError なしに実行できるときのみ（実行適格ゲート。ブールで閾値なし。adaptation-guided retrieval（Smyth & Keane 1998）の「適応可能性が労力を導く」原則を、ランキングではなく修正ティアの選択に1ビット信号で適用した変種。検索ランキング自体は意図的に不変）。ゲート済み候補は生成されず予算も食わない。solve 1回あたりの修正候補の試行は予算 `REVISE_CANDIDATE_LIMIT`=256 で頭打ち（ソース間で共有）。solve は各段階の試行を `report["attempts"]` に全件記録する（テンプレート1件、再利用は事例ごとに最初の失敗例 {input, expected, actual}（DslError 時は actual=null）、修正はソースごとに value_tested／structural_tested／gated／behavior={passed, errors}、探索1件。未解決でも残る）。demo は reason を除いて history に保存し、`cases.py` で往返する。採用された編集は {kind, …} として事例の history に保存される（再生可能性はレビューで双方向に検証済み）。
- 代謝（admission・統計・保持）：解けた事例は格納前に `classify_admission` で absorbed（既存テンプレートの列挙で解ける）／redundant（既存事例の具体化プログラムで解ける）／novel（いずれでもない）のラベルを付ける。各事例は使用統計 stats（reuse_tested／reuse_wins／revise_attempts／revise_wins）を持ち、demo が solve ごとに attempts から加算する。`maintain()` は redundant 事例の削除を候補に、削除後に残り全事例＋削除対象の例題が再解決できる場合のみ確定する（CBR の utility problem、Smyth & Cunningham 1996）。削除された事例の統計はトゥームストーン（{task_id, admission, stats, decision}）として事例ベース側に残る（cases.json は {"removed", "cases"} の新形式で、旧形式のリストも読める）。削除時はテンプレートの support からも対象 ID を取り除く。
- レビュー体制：コーディング＝DeepSeek V4.1 Flash、コードレビュー＝Kimi K2.7 Code、意味論レビュー＝GLM-5.2（いずれも dsh の別プロファイル）。昇格 v1 は両レビューで計11件の指摘を受け全件修正。修正ステップはコードレビューで欠陥ゼロ、意味論レビューでは主張・文書面の指摘を受けて反映済み。代謝ラウンドはコードレビューで中核機構に欠陥なし（周縁4件）、意味論レビューで中程度3件（統計の削除耐性、サイズ台帳の同条件性、support の残存 ID）を受け、修正ラウンドで全件解消した。

## スケッチとの差分（重要・未解消）

- **失敗箇所の診断は依然なし（固定費は一部のみ緩和）。** ゲートの判断材料は「ソースが対象で実行できるか」だけで、失敗位置の同定ではない。記録される失敗観測も最初の失敗例1件（reuse の first_failure）と全例の passed／errors 計数までで、例を跨いだ失敗の分布や出力間の距離は残らない。非実行ソースの構造列挙という固定費はゲートで消えたが、実行はするが修理不能なソースの列挙代は全額のまま。
- **検索ランキングは意図的に不変・決定はデータ待ち。** adaptation-guided retrieval に沿ったランキング変更は先送りした（ブリーフの決定）。今回記録した behavior={passed, errors} はゲートの入力には十分だがランキングの証拠には不十分：passed は「既に完全一致する例の数」で近さを測らず（今回の記録では passed は全行 0）、behavior は試行された修正ソースにしか付かず、現ランキングが弾いた候補にはデータが無い。決定には (i) 全再利用候補への behavior 記録、(ii) 距離付きの失敗観測（全例の actual）、(iii) 保存済み事例ベースを使ったオフラインでのランキング比較再生、が先決。
- **保持まわりの残件はラベルの意味論のみ。** admission ラベルは格納時点のイベント記録で、以後の昇格・削除では更新されない（novel と付いた事例が現在は参照、という読み違えを招く。kept 判定を受けた redundant 事例はラベルだけ見ると削除可能に見える）。トゥームストーン統計と support の掃除は修正ラウンドで解消済み。
- **昇格が扱うのは依然として「解の骨格」で、「修正パターン」の昇格は未実装。** 型はプログラム全体で部品として合成はできず、solve の順序もスケッチの「事例優先」と逆の「型優先」のまま。ただし履歴に失敗側が載ったことで、パターンの適用条件の材料は揃いつつある。
